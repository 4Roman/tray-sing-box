# Sing-Box VPN Tray Manager

Приложение для управления VPN клиентом sing-box через системный трей Windows.

## Возможности

- **Системный трей** с иконкой "4R" на оранжевом фоне
- **Управление VPN**: включение и выключение одним кликом
- **Индикатор состояния**: цветная/серая иконка в трее + текст в меню (Запущен / Запускается… / Остановлен / Запущен (нет связи)); тот же статус виден в веб-интерфейсе
- **Импорт серверов из буфера обмена**: ссылки vless://, vmess://, trojan://, ss://, hysteria2:// (hy2://), а также base64-подписки с несколькими серверами
- **Импорт серверов по QR-коду**: сканирование QR-кода прямо с экрана (все мониторы)
- **Настройки в браузере**: редактирование блоков `outbounds` и `route` как JSON, выбор активного сервера одной кнопкой, импорт; перед сохранением конфиг проверяется через `sing-box check`
- **Обновление sing-box**: проверка и установка последнего релиза с официального GitHub (SagerNet/sing-box) со сверкой с текущей версией
- **Обновление самого приложения** с релизов проекта на GitHub — только подписанные релизы; VPN при этом не прерывается (пункт появляется, когда в сборке заданы репозиторий и ключ, см. «Релизы и автообновление»)
- **Установщик**: `…-setup.exe` ставит приложение в Program Files, данные — в `%ProgramData%`, регистрирует автозапуск и при первом запуске забирает настройки и sing-box прежней переносной копии
- **Обход DPI (zapret в Docker)**: запуск инструмента обхода DPI в Docker-контейнере и подключение его в конфиг по необходимости — цепочкой через активный сервер или как отдельный outbound
- **Подписки**: сохранённые URL, серверы которых синхронизируются в конфиг; обновление из трея, из веб-интерфейса и автоматически (через минуту после старта, далее каждые 6 часов); URL подписки в буфере обмена распознаётся при импорте
- **Проверка связи**: пока VPN запущен, каждые 30 с проверяется реальный выход в интернет
- **Автоперезапуск sing-box**: если sing-box не работает, хотя VPN включён (упал, не поднялся после загрузки Windows), он перезапускается автоматически — до 5 попыток с растущей паузой, затем сообщение об ошибке
- **История конфига**: последние 20 версий `config.json` с откатом из веб-интерфейса
- **Просмотр логов** в веб-интерфейсе
- **Автозапуск**: управление автозапуском через меню с галочкой
- **Сохранение состояния**: запоминает, включил или выключил пользователь VPN, и восстанавливает это при запуске
- **Права администратора**: автоматический запрос прав администратора

## Требования

- Windows 10 или выше (ограничение Go 1.21+)
- Go 1.24 или выше (для сборки)
- sing-box.exe
- config.json (конфигурация sing-box)

## Сборка

1. Установите зависимости:
```bash
go mod download
```

2. Соберите (из WSL, использует Windows-тулчейн Go через interop):
```bash
make
```

Или вручную:

```bash
# Сгенерировать иконки из SVG — ОБЯЗАТЕЛЬНО до сборки: они вшиваются в exe
go run ./tools/genicons

# Собрать приложение (версия попадает в `--version` и в первые строки лога)
go build -trimpath -ldflags="-H windowsgui -X tray-sing-box/internal/config.Version=$(git describe --tags --always --dirty)" -o bin/tray-sing-box.exe .

# Вшить ресурсы Windows в exe (иконка, манифест с правами администратора, версия)
# (один раз: go install github.com/tc-hib/go-winres@v0.3.3)
go-winres patch --in build/winres/winres.json --no-backup bin/tray-sing-box.exe
```

Результат — **один файл** `tray-sing-box.exe`: иконки трея внутри, рядом ничего класть не нужно.

## Установка

**Установщик** (рекомендуется): скачайте `tray-sing-box-<версия>-setup.exe` из релизов и запустите. Он ставит приложение в `Program Files\SingBoxTray`, а данные (config.json, подписки, история, логи) держит в `%ProgramData%\SingBoxTray`; галочка «Запускать при входе в Windows» регистрирует задачу планировщика. `sing-box.exe` в установщик не входит: при первом запуске приложение забирает его вместе с `config.json`, подписками и историей из прежней переносной копии (той, на которую указывала задача автозапуска; старая папка не изменяется и остаётся резервной копией), а если её не было — откройте «Настройки» в меню трея: в разделе «Первоначальная настройка» скачайте sing-box и вставьте свой `config.json` (один раз; его проверяет `sing-box check`, и не принимается то, что позволило бы sing-box запускать программы, читать и писать файлы, менять систему или открыть его в сеть — такой конфиг кладёт в `%ProgramData%\SingBoxTray` администратор). Такое разделение нужно ради безопасности: задача автозапуска запускает exe с правами администратора без запроса UAC, и exe в папке, доступной на запись обычному пользователю, позволил бы любой программе получить эти права при следующем входе. По той же причине установщик ставит только в Program Files, папку данных приложение создаёт так, что доступ к ней есть только у администраторов (в ней ключи серверов и адреса подписок; настройки редактируются через веб-интерфейс), а переносную копию забирает, только если задача автозапуска зарегистрирована с повышенными правами для текущего пользователя. Тихая установка: `…-setup.exe /VERYSILENT` (работающая копия будет закрыта и запущена снова; если она занята долгой операцией и не закрылась за 30 с, установка остановится — повторите позже); тихое удаление сохраняет данные, если не передан `/DELETEDATA=1`.

**Переносная копия** (без установщика):
1. Соберите приложение (см. выше) или возьмите `tray-sing-box-<версия>-windows-amd64.exe` из релиза
2. Положите `sing-box.exe` и `config.json` в одну папку с `tray-sing-box.exe`
3. Запустите `tray-sing-box.exe` (потребуются права администратора)

Переносную копию можно перенести в любую папку — достаточно `tray-sing-box.exe` (иконки вшиты), рядом должны лежать `sing-box.exe` и `config.json`; все её файлы (логи, подписки, история) живут в той же папке. Одновременно работает только один экземпляр: повторный запуск покажет сообщение и завершится.

### Обновление уже установленной копии

- Поставленная установщиком: запустите новый `…-setup.exe` (он попросит работающее приложение выйти, VPN продолжит работать) или воспользуйтесь пунктом «Обновить приложение» в трее
- Переносная:
  1. В меню трея: «Выход» (VPN продолжит работать)
  2. Замените `tray-sing-box.exe` новой сборкой (старую папку `assets/` можно удалить)
  3. Запустите `tray-sing-box.exe` вручную один раз — задача автозапуска, созданная старой версией, сама перерегистрируется с актуальными параметрами (в логе: `Autostart task definition is outdated ... re-registering`)

### Ключи командной строки

`tray-sing-box.exe --version` печатает версию. Остальные ключи служат установщику, но работают и вручную: `--quit` просит работающий экземпляр завершиться (дождавшись конца текущей операции, до 30 с), `--migrate` забирает прежнюю переносную копию (та, на которую указывает задача автозапуска; установщик выполняет это до перерегистрации задачи), `--enable-autostart` / `--disable-autostart` регистрируют или удаляют задачу автозапуска для этого exe, `--uninstall-cleanup` останавливает приложение и sing-box этой папки, удаляет задачу и сохранённое состояние VPN. Из-за манифеста exe все они запрашивают права администратора.

## Использование

После запуска приложение появится в системном трее с иконкой "4R" на оранжевом фоне.

### Меню содержит:

1. **Статус** - показывает текущее состояние VPN: «Остановлен», «Запускается…» (VPN включён, но sing-box ещё не поднялся — приложение пробует само: при загрузке Windows или после падения), «Запущен» или «Запущен (нет связи)» (процесс работает, но проверка интернета не проходит). Иконка в трее цветная при работающем VPN и серая в остальных случаях

2. **Включить/Выключить** - включение или выключение VPN (выполняется именно то действие, которое написано на пункте). В состоянии «Запускается…» пункт называется «Выключить» — так можно отменить попытки запуска

3. **Импорт из буфера обмена** - импорт сервера(ов) из ссылки или base64-подписки в буфере обмена; http(s)-ссылка регистрируется как подписка

4. **Импорт QR с экрана** - поиск QR-кода с ссылкой на сервер на экране и его импорт

5. **Обновить подписки** - заново скачивает все сохранённые подписки (устаревшие серверы удаляются, переименованный провайдером сервер остаётся на своём месте и выбранным; VPN перезапускается только при реальном изменении конфига). О проблеме автообновления (подписка не скачивается больше суток, серверы пропущены) приложение сообщает один раз

6. **Настройки** - открывает веб-интерфейс настроек в браузере

7. **Обновить sing-box** - проверяет последний релиз на GitHub и обновляет sing-box.exe, если он новее установленного

7а. **Обновить приложение** - (только если в сборке настроено автообновление) проверяет релизы проекта на GitHub, устанавливает подписанный релиз и предлагает перезапуститься; VPN не прерывается

8. **Обход DPI (zapret)** - галочка: поднимает zapret в Docker и заворачивает подключение активного сервера через него (обход DPI на самом VPN-подключении)
   - ✓ Галочка означает, что цепочка через zapret включена
   - Работает только с TCP-серверами (vless/trojan/vmess); для hysteria2/tuic (UDP) недоступно
   - Требуется запущенный Docker Desktop

9. **Автозапуск** - управление автозапуском при старте Windows
   - ✓ Галочка означает, что автозапуск включен **для этой копии приложения** (задача существует, не отключена и запускает именно этот exe)
   - Нажмите для включения/выключения автозапуска; ошибка показывается во всплывающем окне

10. **Выход** - закрытие приложения (VPN продолжает работать в фоне; сохранённое состояние не меняется)

### Обновление sing-box:

- Текущая версия определяется через `sing-box version`, последняя — через GitHub API (релизы SagerNet/sing-box)
- Обновление выполняется только если релиз новее установленной версии (даунгрейда нет)
- Скачивается zip под архитектуру системы, бинарник проверяется запуском до установки
- Старый бинарник сохраняется как `sing-box.exe.old` и восстанавливается при сбое
- Если VPN был запущен — он останавливается только на время замены файла и запускается снова

### Обход DPI (zapret в Docker):

- Инструмент zapret запускается в Docker-контейнере (`8hrsk/zapret-docker-proxy`, режим `--privileged`) и публикует HTTP-прокси на `127.0.0.1:3128`; десинхронизацию DPI делает nfqws на исходящем трафике контейнера
- **Цепочка (режим A)** — галочка «Обход DPI» в трее или кнопка в веб-интерфейсе: к активному прокси-серверу добавляется `detour` на `dpi-bypass`, и подключение к VPN-серверу идёт через zapret. Подходит, когда провайдер блокирует сам VPN-сервер по DPI
  - Только для TCP-серверов (`vless`/`trojan`/`vmess`): HTTP-прокси не пропускает UDP, поэтому для `hysteria2`/`tuic` режим отклоняется с понятным сообщением
- **Прямой обход (режим B)** — в веб-интерфейсе кнопка «Подготовить прямой обход», затем выберите `dpi-bypass` в списке серверов: трафик идёт через zapret без VPN/шифрования
- Требуется установленный и запущенный Docker Desktop; иначе обе точки входа показывают «Docker не найден или не запущен…», а трей продолжает работать без зависаний
- Контейнер стартует до правки конфига; при выключении цепочки контейнер останавливается, если прямой обход его не использует
- Параметры стратегии nfqws (под конкретного провайдера) можно задать в файле `dpi-params.txt` рядом с `tray-sing-box.exe` — он передаётся как `ZAPRET_PARAMS` при создании контейнера (смена требует пересоздания контейнера)

### Релизы и автообновление приложения

- Релиз собирает GitHub Actions по тегу вида `v1.2.3` (`.github/workflows/release.yml`) как **черновик** с двумя файлами: `tray-sing-box-<версия>-windows-amd64.exe` (его скачивает автообновление) и установщиком `tray-sing-box-<версия>-setup.exe` (Inno Setup, `build/installer/`). Подпись CI **не делает** — намеренно
- Приложение принимает релиз, только если `checksums.txt` подписан ключом проекта (ed25519): оно работает с правами администратора и запускает то, что скачало, поэтому одной контрольной суммы недостаточно — её опубликует и взломанный аккаунт GitHub. По той же причине закрытый ключ нельзя класть в секреты CI: взломанный аккаунт тогда просто пушит тег, и CI подписывает что угодно. Ключ хранится только у мейнтейнера
- Разовая настройка (после создания репозитория):
  1. `go run ./tools/relkey -out <файл вне репозитория>` — печатает открытый ключ и пишет закрытый в указанный файл (по умолчанию `%USERPROFILE%\tray-sing-box-release-signing-key.txt`; путь внутри git-репозитория relkey отвергает); закрытый ключ убрать в менеджер паролей / на зашифрованный носитель
  2. открытый ключ — в `internal/config/config.go` (`AppUpdatePublicKey`), туда же `AppUpdateRepo = "owner/repo"`; закоммитить (workflow отказывается собирать релиз, пока они пустые — иначе первая версия никогда не смогла бы обновиться)
- Каждый релиз:
  1. `git tag -a v1.2.3 -m v1.2.3 && git push origin v1.2.3` — CI собирает и создаёт **черновик** релиза (exe + установщик)
  2. `build\release\finish-release.ps1 -Tag v1.2.3 -KeyFile <файл с закрытым ключом> [-SingBoxDir <папка с sing-box.exe>] [-Publish]` — скачивает exe черновика, **пересобирает его из тега** с настройками CI (toolchain из `go.mod`, `CGO_ENABLED=1`, `-trimpath`, go-winres v0.3.3) и требует совпадения SHA-256 (сборка воспроизводима бит в бит — проверено на `v1.0.0`), собирает установщик из проверенного exe локально (Inno Setup 6.7.3) и заменяет им установщик черновика, с `-SingBoxDir` прогоняет тест установщика в Windows Sandbox, подписывает `checksums.txt` (`tools/relsign -key-file`) и загружает подпись; с `-Publish` публикует. Зачем пересборка: подпись без неё заверяла бы всё, что собрал CI, — в том числе результат взломанного действия GitHub Actions (они к тому же закреплены по SHA коммитов). Ключ — из файла, не в командной строке: её сохраняет история оболочки
  3. без `-Publish` — проверить черновик и опубликовать (`gh release edit v1.2.3 --draft=false --latest`). Клиенты не видят черновиков и отвергают релизы без подписи, так что забытый шаг даёт «обновлений нет», а не плохое обновление
- Проверка установщика — в Windows Sandbox, не на рабочей машине: `build\installer\sandbox\run.ps1 -SingBoxDir <папка с sing-box.exe> [-Setup <…-setup.exe>] [-Exe <…-windows-amd64.exe>]` (по умолчанию — `dist\tray-sing-box-0.0.0-setup.exe` и `bin\tray-sing-box.exe`). В одноразовой Windows ставит переносную копию с автозапуском и включённым VPN, затем тихо устанавливает поверх (перенос, задача перенацелена, VPN поднят из Program Files, права папки данных), обновляет (sing-box не прерывается), удаляет с сохранением данных, ставит заново и запускает через задачу, удаляет с `/DELETEDATA=1` при работающей переносной копии; итог — `results\summary.txt`, код выхода 0 при успехе. Песочницу включают один раз (PowerShell от администратора, затем перезагрузка): `Enable-WindowsOptionalFeature -Online -FeatureName Containers-DisposableClientVM -All`
- Жизненный цикл установленной копии — тоже в Windows Sandbox, через её командную строку `wsb` (Windows 11 24H2 и новее: команды в работающей песочнице и перезагрузка внутри неё): `build\installer\sandbox\lifecycle.ps1 -Setup <…-setup.exe> -SingBoxDir <папка с sing-box.exe>` (PowerShell 7). Этапы по очереди: установка и восстановление VPN задачей, импорт из буфера обмена и QR с экрана (`import-qr.png`), падение sing-box (монитор перезапускает, в логе `ERROR`), перезапуск Проводника (значок возвращается), выключение из меню трея (намерение 0, без `ERROR`), перезагрузка с выключенным VPN (остаётся выключенным) и с включённым (восстанавливается с первой попытки), выход (sing-box продолжает работать). `-Phases fresh,web -Network` проверяет страницу настроек на чистой установке в настоящем Edge: ссылка из трея, код убран из адреса, «Скачать sing-box», отказ guard, первый config.json, скрытые учётные данные, включение VPN со страницы, перезагрузка страницы без сеанса. В песочнице UAC выключен, и всё работает с полными правами; `-Uac` включает его (повышение без запроса) — тогда проверяется то же, что у пользователя: Проводник и браузер ниже приложения, установщик, запущенный из Проводника через мастер (`-Phases interactive`), отказ тихой установки не в Program Files (`dir-refused`, код 7). `-Network -Phases install,singbox-update` — «Обновить sing-box» при работающем VPN (скачивание, замена с `.old`, перезапуск). Итоги — `results\<этап>.txt`, код выхода 0 при успехе
- Обновление: скачивание рядом с exe → проверка подписи и суммы → запуск скачанного файла с `--version` → переименование (текущий exe остаётся как `tray-sing-box.exe.old`) → по подтверждению перезапуск в новую версию (`--wait-pid`); sing-box всё это время работает. Проверка новых версий — через 2 минуты после старта и раз в сутки, только у релизных сборок; dev-сборка (`--version` не вида `v1.2.3`) обновляется только по кнопке

### Настройки (веб-интерфейс):

- **Первоначальная настройка** (только пока `config.json` нет — установленная копия на чистой машине) — кнопка «Скачать sing-box» и поле для первого `config.json`. Сохраняется один раз (существующий конфиг не заменяется), после `sing-box check`. Приложение не примет то, что дало бы sing-box (он работает с правами администратора) больше, чем нужно VPN-клиенту: разделы кроме `log`, `dns`, `ntp`, `certificate`, `inbounds`, `outbounds`, `endpoints`, `route`, `experimental`; inbound кроме `tun`, `mixed`, `socks`, `http`, `direct`; endpoint кроме `wireguard` (и без `listen_port`); прослушивание не на 127.0.0.1 (inbound, clash/v2ray API), `experimental.debug`; пути к файлам и папкам (`*_path`, `*_directory`, `log.output`, `external_ui`, `masquerade`; в папке данных можно `cache_file.path` и локальный rule-set по имени файла); `ntp.write_to_system`. Отказ перечисляет такие места без значений
- **Активный сервер** — список всех outbounds; выберите сервер и нажмите «Использовать выбранный»: все правила маршрутизации, указывающие на прокси (и `route.final`, если он указывал на прокси), переключаются на выбранный сервер
- **Импорт** — кнопки импорта из буфера обмена и QR с экрана
- **Подписки** — добавить URL, обновить одну/все, удалить; автообновление каждые 6 часов
- **Обновление sing-box** — та же операция, что и пункт трея
- **Обновление приложения** — версия, последний релиз, кнопки «Проверить и обновить» и «Перезапустить в новую версию» (секция видна только в сборке с настроенным автообновлением)
- Кнопка **Включить/Выключить** рядом со статусом VPN в шапке — то же, что пункт трея
- **Обход DPI** — статус Docker/контейнера, кнопки цепочки и прямого обхода
- **Outbounds / Route (JSON)** — редактирование секций конфига текстом; перед сохранением проверяется корректность JSON и, если sing-box.exe рядом, конфиг прогоняется через `sing-box check`
- **История конфига** — последние 20 версий `config.json` (папка `config-history/`); откат проходит обычную проверку и сам обратим
- **Логи** — хвосты (64 КБ) `tray-sing-box.log`, лога sing-box (если в `config.json` задан `log.output`) и вывода sing-box в консоль (`sing-box-console.log`), автообновление раз в 3 с
- Любое изменение автоматически перезапускает VPN, если он запущен
- Интерфейс доступен только с этого компьютера (127.0.0.1). Вход — по одноразовой ссылке из пункта трея «Настройки»; сеанс живёт только в открытой странице: после перезагрузки страницы или через 30 минут бездействия откройте «Настройки» из трея заново
- Пароли, uuid и ключи серверов показываются как «(скрыто)»: оставленное как есть поле сохраняет прежнее значение, но чтобы изменить адрес или другие параметры сервера, скрытые поля нужно ввести заново. Адреса подписок показываются без токена: `https://host/… (a1b2c3)`

### Импорт серверов:

- Поддерживаемые ссылки: `vless://`, `vmess://`, `trojan://`, `ss://` (SIP002 и legacy), `hysteria2://`, `hy2://`
- Если в тексте несколько ссылок или это base64-подписка — импортируются все серверы сразу
- Outbound добавляется в `config.json`, тег регистрируется во всех группах selector/urltest. Сервер с тем же тегом заменяется — повторный импорт обновляет сервер (его `detour`, например цепочка обхода DPI, сохраняется). Но `direct`, `block`, `dns`, группы selector/urltest, `dpi-bypass` и серверы подписок импорт не заменяет: новый сервер сохраняется как «имя (2)», и окно с результатом об этом говорит
- Ссылка, которую не удалось разобрать, и сервер, который не принимает `sing-box check`, пропускаются — остальные импортируются; окно с результатом перечисляет пропущенные (имя и причина, без самой ссылки). Так же и в подписках: один неподходящий сервер провайдера не останавливает её обновление
- Перед изменением создаётся резервная копия `config.json.bak`
- Если VPN запущен — он автоматически перезапускается с новым конфигом
- Результат импорта показывается во всплывающем окне

### Сохранение состояния VPN:

- **VPN работает независимо от приложения трея**: sing-box.exe продолжает работать даже после закрытия приложения
- При включении/выключении VPN **пользователем** его намерение сохраняется в реестре Windows (`HKCU\Software\SingBoxTray`, значение `VPNRunning`)
- Сохраняется именно намерение, а не наблюдаемое состояние процесса: при выходе из приложения, при завершении работы Windows, при падении sing-box и при служебных перезапусках (смена конфига, обновление бинарника) в реестр ничего не пишется
- При следующем запуске (в том числе при автозапуске) приложение автоматически восстанавливает последнее состояние:
  - Если VPN был включен - подключается к уже работающему процессу sing-box или запускает новый
  - Если VPN был выключен - не запускает sing-box
- Восстановление начинается сразу при старте приложения, не дожидаясь готовности панели задач: до 3 попыток с проверкой, что процесс выжил (после загрузки Windows сеть/драйверы могут быть не готовы). Если не получилось — дальше пробует монитор (см. ниже)
- Пока намерение «включён», а sing-box не работает (упал, не поднялся при загрузке), монитор перезапускает его: до 5 попыток с паузами 5/10/15/20 с, затем показывает сообщение с последней ошибкой и вопросом «Выключить VPN?» («Да» записывает намерение «выключен» — иначе попытки и сообщение повторятся при следующем входе). Счётчик сбрасывают: явное включение/выключение из меню, сохранение конфига и успешное обновление sing-box
- При закрытии приложения через меню "Выход" VPN продолжает работать, что позволяет сохранить интернет-соединение

## Примечания

- Приложение автоматически запрашивает права администратора при запуске
- Консольное окно sing-box скрывается при запуске
- **При закрытии приложения VPN продолжает работать в фоновом режиме**
- Для полной остановки VPN сначала выключите его через меню, затем закройте приложение
- **Две раскладки файлов**: переносная (всё рядом с exe) и установленная (exe и `sing-box.exe` в `Program Files\SingBoxTray`, данные в `%ProgramData%\SingBoxTray`). Определяется по расположению exe: `config.json` рядом с exe всегда означает переносную. sing-box запускается с рабочей папкой = папка данных, поэтому относительные пути в `config.json` (`log.output`, `cache_file`, rule-set'ы) отсчитываются от неё
- **Логирование**: события приложения записываются в `tray-sing-box.log` в папке данных — рядом с exe у переносной копии, в `%ProgramData%\SingBoxTray` у установленной (в первых строках — версия сборки и раскладка: `Layout: portable…` / `Layout: installed…`). Вывод самого sing-box идёт в отдельный файл `sing-box-console.log` (sing-box пишет в него напрямую, поэтому лог не теряется, когда приложение трея закрыто); если в `config.json` задан `log.output`, основной лог sing-box будет там, а в `sing-box-console.log` останется только то, что он печатает до запуска логгера (например, фатальная ошибка конфига). Оба файла ограничены 10 МБ, старое содержимое уходит в `*.old` (предыдущий `.old` заменяется): лог приложения — при его старте; лог sing-box — при запуске sing-box, а пока sing-box работает, проверяется раз в 30 минут
- **Docker для обхода DPI** запускается только из места установки Docker Desktop (`C:\Program Files\Docker\Docker\resources\bin\docker.exe`) и только если этот файл и все папки над ним нельзя изменить без прав администратора; настройки `%USERPROFILE%\.docker` не используются (своя папка в данных приложения). Приложение работает с правами администратора, и иначе подложенный `docker.exe` или помощник из пользовательского конфига docker запускались бы с этими правами при каждом старте
- **Через приложение в конфиг нельзя добавить то, что даёт sing-box запускать программы или писать файлы** (outbound `tor`, пути к сертификатам и ключам, `log.output`, путь кэша, внешний UI и т. п.): sing-box работает с правами администратора, а веб-интерфейсом может воспользоваться и программа без этих прав. Сохранение с такими параметрами отклоняется с сообщением; то, что уже есть в `config.json` (вписано администратором вручную), остаётся и работает
- **Загрузки с проверкой по сертификатам машины**: sing-box, обновления приложения и подписки скачиваются без прокси из переменных окружения и с проверкой TLS только по корневым сертификатам машины — сертификат, добавленный программой в хранилище пользователя, не принимается; подписка по `https://` с IP-адресом вместо имени не поддерживается
- **Страница настроек открывается в браузере без прав администратора** (от имени рабочего стола): программа, открывающая ссылки, выбирается и в пользовательской части реестра, и открывать её от имени администратора нельзя. Если так открыть не удалось, приложение покажет адрес — его можно вставить в браузер вручную
- **Чужой sing-box не трогается**: приложение ищет и завершает только свой `sing-box.exe` (по полному пути к файлу рядом с exe), а не любой процесс с таким именем
- **Автозапуск**: использует Планировщик задач Windows (Task Scheduler) для запуска с правами администратора
  - Задача создается с именем "SingBoxTray" через XML-конфигурацию
  - Запускается при входе пользователя с наивысшими привилегиями и обычным приоритетом (`<Priority>4</Priority>`; приоритет планировщика по умолчанию — 7 — запускал и приложение, и sing-box с пониженным приоритетом CPU/диска/памяти)
  - VPN восстанавливается сразу; иконка в трее появляется, когда готова панель задач (ожидание до 10 минут — VPN от него не зависит)
  - Задача привязана к конкретному exe: запуск другой копии приложения (например, сборки из репозитория) её не перенастраивает; галочка «Автозапуск» в другой копии будет снята, нажатие на неё перерегистрирует задачу на эту копию

## Решение проблем

### Приложение не запускается
- Убедитесь, что вы запускаете приложение с правами администратора
- Проверьте, что `sing-box.exe` лежит рядом с `tray-sing-box.exe` (у установленной копии — в `Program Files\SingBoxTray`), а `config.json` — в папке данных (рядом с exe или в `%ProgramData%\SingBoxTray`)

### VPN не включается
- Убедитесь, что файл config.json существует и корректен
- Проверьте логи sing-box

### Автозапуск не работает (иконка в трее не появляется)
- **Проверьте лог-файл** `tray-sing-box.log` (рядом с exe; у установленной копии — в `%ProgramData%\SingBoxTray`). При нормальном старте идут записи (восстановление VPN и ожидание трея выполняются параллельно, поэтому их строки могут чередоваться):
  - `=== Application started ===`
  - `Restoring VPN state: true|false`, при `true` — `VPN state restored on attempt N` (или `Restore attempt N/3 failed: ...`, после чего попытки продолжает монитор: `auto-restarting (attempt N/5)`)
  - `Waiting for Windows shell (system tray) to be ready...`
  - `System tray is ready (attempt N/600)` (или `Timeout waiting for system tray, proceeding anyway...`)
- Если в логе при выключении Windows есть `VPN state saved: running=false` / `Application exiting. VPN state saved: false`, а при старте — `Waiting for Windows Explorer to be ready...`, то запущена **старая сборка** (до июня 2026): она затирала сохранённое состояние при завершении работы Windows, поэтому VPN не включался после перезагрузки. Замените exe новой сборкой (см. «Обновление уже установленной копии»). Какая сборка запущена, видно по строке `Version: ...` в начале лога (у старых сборок её нет)
- Откройте Планировщик задач Windows (`Win+R` → `taskschd.msc`)
- Проверьте наличие задачи "SingBoxTray"
- Убедитесь, что задача настроена на запуск при входе пользователя
- Проверьте, что путь к приложению в задаче корректен. После установки поверх переносной копии задача должна указывать на `Program Files\SingBoxTray\tray-sing-box.exe` — её перенацеливает галочка установщика; если галочку сняли, включите «Автозапуск» в меню установленной копии (иначе при входе стартует старая переносная копия)
- Попробуйте запустить задачу вручную: ПКМ на задаче → "Выполнить"
- После перезагрузки приложение автоматически ждет готовности системного трея (это может занять несколько секунд)

### VPN не включился после перезагрузки
- В реестре `HKCU\Software\SingBoxTray` значение `VPNRunning` должно быть `1` — оно пишется только при явном включении/выключении из меню
- В логе найдите `Restoring VPN state:`. Если там `false`, хотя VPN вы включали — см. пункт про старую сборку выше
- Если `true`, но sing-box не поднимается — рядом будут `Restore attempt ... failed` / `auto-restarting (attempt N/5)` с причиной (текст ошибки самого sing-box; полностью — в `sing-box-console.log`); после 5 неудачных попыток появится окно с последней ошибкой. Пока идут попытки, статус в меню — «Запускается…», и их можно отменить пунктом «Выключить»
